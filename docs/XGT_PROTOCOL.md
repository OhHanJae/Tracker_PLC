# XGT 연속 BYTE 통신 구현 기준

이 구현은 제공된 `XGT 전용통신(2).pdf`의 서버 서비스 규격을 기준으로 합니다.

## 적용 명령

| 기능 | 요청 | 응답 | 데이터 형식 |
|---|---:|---:|---:|
| 변수 연속 읽기 | `0x0054` | `0x0055` | `0x0014` (연속 BYTE) |
| 변수 연속 쓰기 | `0x0058` | `0x0059` | `0x0014` (연속 BYTE) |

다중 블록이 아니라 **블록 수 1개**만 사용합니다. 요청 가능 길이는 1~1,400바이트이며 기본값은 100바이트입니다.

## 20바이트 Company Header

| Offset | 크기 | 필드 | 송신값 |
|---:|---:|---|---|
| 0 | 10 | Company ID | `LSIS-XGT 00 00` |
| 10 | 2 | PLC Info | `0x0000` |
| 12 | 1 | CPU Info | 기본 `0xA0` (XGK), 설정 가능 |
| 13 | 1 | Source of Frame | 요청 `0x33`, 응답 `0x11` |
| 14 | 2 | Invoke ID | 요청/응답 대응 번호 |
| 16 | 2 | Length | 명령어부터 데이터 끝까지의 바이트 수 |
| 18 | 1 | Ethernet 위치 | 상위 4비트 Base, 하위 4비트 Slot |
| 19 | 1 | BCC | Offset 0~18의 합 하위 1바이트 |

2바이트 이상의 수치는 프레임에서 little-endian입니다. 예를 들어 `0x0054`는 `54 00` 순서로 전송됩니다.

## 연속 읽기 요청 Body

| 순서 | 크기 | 내용 |
|---:|---:|---|
| 1 | 2 | 명령 `0x0054` |
| 2 | 2 | 데이터 형 `0x0014` |
| 3 | 2 | 예약 `0x0000` |
| 4 | 2 | 블록 수 `0x0001` |
| 5 | 2 | 변수명 ASCII 길이 |
| 6 | N | 변수명, 예: `%DB2000` |
| 7 | 2 | 읽을 BYTE 수, 기본 100 |

Body 길이는 `12 + 변수명 길이`입니다.

## 연속 쓰기 요청 Body

읽기 요청과 앞부분이 같고, BYTE 수 다음에 실제 데이터가 붙습니다.

| 순서 | 크기 | 내용 |
|---:|---:|---|
| 1~6 | - | 명령 `0x0058`, 형 `0x0014`, 예약, 블록 수 1, 변수명 길이/변수명 |
| 7 | 2 | 쓸 BYTE 수, 기본 100 |
| 8 | BYTE 수 | 실제 데이터 |

Body 길이는 `12 + 변수명 길이 + 데이터 길이`입니다.

## D영역 주소 환산

매뉴얼에서 BYTE 타입 주소는 WORD 주소의 2배입니다.

| 사용자가 입력 | 실제 XGT 변수명 | 100바이트가 의미하는 범위 |
|---|---|---|
| `D0` | `%DB0` | D0~D49 |
| `D100` | `%DB200` | D100~D149 |
| `D1000` | `%DB2000` | D1000~D1049 |
| `%DW1000` | `%DB2000` | D1000~D1049 |
| `%DB2000` | `%DB2000` | D1000~D1049 |

다른 디바이스 영역은 단위 오해를 막기 위해 `%MB0`처럼 BYTE 직접 변수로 입력합니다.

## 공유 메모리 안의 WORD 바이트 순서

Gateway는 연속 BYTE 응답을 가공하거나 스왑하지 않고 그대로 RX 공유 메모리에 복사합니다. XGK의 D WORD 값이 `0x1234`라면 일반적으로 연속 BYTE에는 하위 바이트부터 `34 12`로 보입니다. 파이썬에서 WORD로 해석할 때는 little-endian을 사용합니다.

```python
import struct

d0 = struct.unpack_from("<H", plc_bytes, 0)[0]
d1 = struct.unpack_from("<H", plc_bytes, 2)[0]
```

반대로 PLC에 WORD `0x1234`를 쓰려면 TX 버퍼에 `struct.pack("<H", 0x1234)`로 `34 12`를 넣습니다.

## ACK/NAK 확인

- 읽기 ACK: 명령 `0x0055`, 에러 상태 0, 블록 수 1, 데이터 길이, 데이터
- 쓰기 ACK: 명령 `0x0059`, 에러 상태 0, 블록 수 1
- NAK: 에러 상태가 0이 아니며 다음 2바이트가 에러 코드

Gateway는 Company ID, Source, Invoke ID, 명령, 데이터 형, 블록 수, 응답 길이를 모두 검사합니다. TCP 분할 수신에도 대응하도록 헤더 20바이트와 `Length`만큼의 Body를 각각 완전히 수신합니다.

## 주요 에러 코드

| 코드 | 의미 |
|---:|---|
| `0x0001` | 개별 요청 블록 수 초과 |
| `0x0002` | 지원하지 않는 데이터 형 |
| `0x0003` | 지원하지 않는 디바이스 |
| `0x0004` | 디바이스 영역 초과 |
| `0x0005` | 개별 블록 1,400바이트 초과 |
| `0x0006` | 전체 블록 크기 초과 |
| `0x0075` | Company Header 오류 |
| `0x0076` | Length 오류 |
| `0x0077` | Checksum 오류 |
| `0x0078` | 명령어 오류 |
